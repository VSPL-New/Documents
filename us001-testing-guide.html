User Registration via Mobile OTP — QA Testing Guide

End-to-end test sequence for the full registration and Aadhaar verification flow using Swagger UI against a local dev environment.

Base URL: http://localhost:8080 Swagger: /swagger-ui.html OTP Provider: mock Aadhaar Provider: sandbox
01
Initiate Registration
Registers the mobile number and triggers an OTP. No authentication required.
POST /api/v1/auth/register/initiate PUBLIC
Request body
{
  "mobile":        "9876543210",
  "termsAccepted": true,
  "consentGiven":  true
}
→ Check the application console log for the OTP. Look for:
[DEV-MOCK] OTP for mobile=9876543210 purpose=MOBILE_VERIFY otp=XXXXXX
Expected response — 200 OK
{
  "success": true,
  "data": {
    "message":              "OTP sent to your mobile number",
    "otpExpiresInSeconds":  300
  }
}
02
Verify Mobile OTP
Validates the OTP and issues a JWT. Copy the accessToken from the response — needed for steps 4 and 5.
POST /api/v1/auth/register/verify-mobile PUBLIC
Request body
{
  "mobile": "9876543210",
  "otp":    "XXXXXX"   ← value from console log
}
Expected response — 200 OK
{
  "success": true,
  "data": {
    "accessToken":    "eyJhbGci...",  ← copy this
    "refreshToken":   "eyJhbGci...",
    "aadhaarVerified": false,
    "userId":         "uuid-here"
  }
}
✓ User state after this step: account transitions to IDENTITY_VERIFICATION_PENDING. The JWT has aadhaarVerified: false.
03
Authorize in Swagger UI
Set the Bearer token so subsequent requests include the Authorization header automatically.
1
Click the Authorize 🔒 button in the top-right of the Swagger UI page.
2
In the bearerAuth field, paste the accessToken value only — no Bearer prefix. Swagger adds it automatically.
3
Click Authorize then Close. All subsequent requests will send Authorization: Bearer <token>.
04
Initiate Aadhaar Verification
Starts the Aadhaar OTP flow via the sandbox provider. Copy the transactionId from the response.
POST /api/v1/auth/aadhaar/initiate JWT REQUIRED
Request body
{
  "aadhaarNumber": "123456789012",
  "consentToken":  "consent-ts-123"
}
Expected response — 200 OK
{
  "success": true,
  "data": {
    "transactionId": "sandbox-txn-..."   ← copy this
  }
}
→ The sandbox provider generates a transactionId prefixed sandbox-txn-. No real Aadhaar OTP is sent.
05
Complete Aadhaar Verification
Validates the sandbox OTP and transitions the account to ACTIVE. Issues a new JWT with aadhaarVerified: true.
POST /api/v1/auth/aadhaar/verify JWT REQUIRED
Request body
{
  "transactionId": "sandbox-txn-...",  ← from step 4
  "otp":           "123456"             ← sandbox pass code
}
Expected response — 200 OK
{
  "success": true,
  "data": {
    "accessToken":    "eyJhbGci...",
    "refreshToken":   "eyJhbGci...",
    "aadhaarVerified": true,   ← account is now ACTIVE
    "userId":         "uuid-here"
  }
}
✓ Registration complete. Account state is ACTIVE. Use the new accessToken for all marketplace API calls.
! Sandbox only accepts "123456" as the passing OTP. Any other value returns an Aadhaar verification failure.
Common errors
HTTP Error code Cause & fix
401 UNAUTHORIZED Missing or expired JWT on a protected endpoint. Repeat steps 2–3 to get a fresh token.
400 ERROR_OTP_EXPIRED OTP TTL is 300 s. Re-run step 1 to generate a new one.
400 ERROR_INVALID_OTP Wrong OTP value. Check the console log for the correct 6-digit code.
400 ERROR_OTP_MAX_ATTEMPTS 5 failed OTP attempts within the 10-minute window. Wait for the window to reset or use a different mobile number.
400 ERROR_MOBILE_ALREADY_REGISTERED Mobile already has an account. Use a different number or clear the users table in the dev DB.
400 ERROR_AADHAAR_ALREADY_LINKED The Aadhaar number is linked to another account. Use a different 12-digit number in step 4.
